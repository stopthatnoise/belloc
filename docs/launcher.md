# Лаўнчар, каталог перакладаў і версіі

Мэта: праграма, якая сама бачыць на камп'ютары гульні з беларускім перакладам,
ставіць і абнаўляе яго і нагадвае пра новыя версіі.

- `launcher/games.py` — логіка без інтэрфейсу: што знойдзена, стан, паставіць, выдаліць;
- `launcher/app.py` — акно (PySide6): карткі гульняў з вокладкамі з лакальнага кэша
  Steam, кнопкі «Усталяваць» / «Абнавіць да X» / «Паставіць нанова» / «Выдаліць»,
  журнал; доўгія справы — у асобным патоку;
- `launcher/main.py` — тое ж у кансолі.

```bash
python launcher/app.py [--catalog <url|файл>]     # акно; залежнасць — extra "launcher"
python launcher/main.py list                      # кансоль
```
Пакуль толькі Steam; іншыя крамы (GOG, Epic) — праз поле `stores`.

```
catalog.json (публічна) ──► лаўнчар / exe: ці ёсць пераклад і якая версія навейшая
пакет <гульня>-<версія>.zip ──► лаўнчар: payload.json + assets/ → engine.apply
<каталог гульні>/belloc.json ◄── хто паставіў, якую версію, пад які buildid
```

## Каталог — `core/belloc/catalog.py`

Адзін публічны `catalog.json`: па запісе на гульню — назва, крамы (`{"steam": appid}`),
рухавік, `payload_schema`, версія, дата, `changes`, `steam_buildid` (пад якую версію
гульні), exe гульні, назва мовы і якую яна замяняе, старонка рэліза, пакет (`url`,
`sha256`, `size`) і `probe` — payload без тэксту, каб спытаць `engine.installed()`
да спампоўкі. Поўны прыклад — у docstring `catalog.py`.

**Дзе ляжыць.** Пакуль belloc закрыты, лаўнчар тэстуецца на часовым публічным
рэпазіторыі [stopthatnoise/belloc-catalog](https://github.com/stopthatnoise/belloc-catalog):
`catalog.json` у `main`, пакеты — у Releases (тэг `<гульня>-v<версія>`). Калі belloc
адкрыецца, `CATALOG_URL` і `RELEASES` у `catalog.py` пераключаюцца на яго, а
belloc-catalog выдаляецца. exe, сабраныя да гэтага, проста перастануць нагадваць пра
новыя версіі (без сеткі і без каталога ўсталёўшчык працуе як звычайна).

**Сумяшчальнасць.** `payload_schema` большы, чым `payload.SCHEMA` у лаўнчары, або
невядомы рухавік → «патрэбна новая версія лаўнчара»: стары код не ламае гульню
новым фарматам. `launcher` у каталогу — пад версію і спасылку самога лаўнчара (пазней).

**Прыватнасць.** Кліент толькі спампоўвае `catalog.json` і пакет — адзін GET, без
тэлеметрыі. Спіс гульняў карыстальніка нікуды не адпраўляецца: супастаўленне з
каталогам — на яго камп'ютары.

## Пакет перакладу

`<гульня>-<версія>.zip`: `payload.json` (наш тэкст па ключах + апісанне рэліза) і
`assets/` (вольныя шрыфты) — тое ж, што ўсярэдзіне exe. Кода ў пакеце няма, рухавікі —
у лаўнчары: новая версія перакладу — некалькі мегабайт без новага exe. Пакет
сабраны дэтэрмінавана (сталыя час і парадак файлаў); лаўнчар правярае `sha256`
з каталога перад усталёўкай.

## Што бачыць гулец

- **«Вашы гульні»** — гульні з каталога, знойдзеныя ў бібліятэках Steam або ў папках,
  пазначаных уручную; кнопкі — па стане перакладу (ніжэй).
- **«Ёсць пераклад, але гульні няма на гэтым камп'ютары»** — астатнія пераклады
  каталога: версія, што перакладзена (`contents` у каталогу), «Старонка ў Steam».
- Нічога не знайдзена — загаловак «Пакуль няма гульняў з беларускім перакладам» і
  ўвесь каталог; Steam не знойдзены — «Steam не знойдзены».
- **«Гульня ўсталявана ў іншае месца? Пазначыць папку»** — гулец паказвае папку
  гульні; лаўнчар пазнае яе па тым, па чым пазнае рухавік (`check_path`), і па exe
  гульні (да двух узроўняў углыб). Папка запамінаецца ў
  `%LOCALAPPDATA%/belloc/launcher.json`. Гэтым жа шляхам пазней пойдуць GOG і Epic,
  пакуль іх няма ў пошуку.
- Даты — `31.10.2026`; у даных (каталог, метка) — ISO.

## Метка ўсталёўкі — `belloc.json` у каталогу гульні

Піша і выдаляе ўсё, што ставіць пераклад: exe (`by: installer`), лаўнчар
(`launcher`), `belloc patch`. Стан лаўнчар бярэ з меткі і `engine.installed()`
(`install/state.py: status`):

| стан | што значыць | што прапануе |
|---|---|---|
| `none` | перакладу няма | паставіць |
| `installed` | стаіць версія з меткі | абнавіць, калі ў каталогу навейшая |
| `wiped` | метка ёсць, нашых файлаў няма — Steam абнавіў або праверыў гульню | паставіць нанова |
| `unknown` | файлы нашы, меткі няма — паставіў стары exe | паставіць (каб з'явілася метка) |

Калі `buildid` гульні не той, што ў каталогу, — папярэджанне: новыя радкі могуць
быць неперакладзенымі.

## Напаміны пра новую версію

- **exe-усталёўшчык** пры запуску правярае каталог (3 с; без сеткі — моўчкі
  далей): «ёсць новая версія 1.2 — спампаваць: <старонка>».
- **лаўнчар** паказвае «ёсць новая версія» ля кожнай гульні.

## Як выпусціць версію

```bash
python -X utf8 -m belloc package <гульня>      # exe + ЧЫТАЙ.txt
python -X utf8 -m belloc catalog <гульня>      # пакет + запіс у local/catalog/catalog.json
```

`local/catalog/` — лакальная копія belloc-catalog (`git clone`). Далей:
`gh release create <гульня>-v<версія> <пакет> <exe-zip> --repo stopthatnoise/belloc-catalog`,
закамітаць і запушыць `catalog.json`. Версія — `release.version` у game.json,
што змянілася — `release.changes` (кароткі радок) і `CHANGELOG.md` гульні.
Пазней гэта зробіць CI па тэгу.

## Далей

- exe лаўнчара (PyInstaller з усімі рухавікамі) і яго самаабнаўленне праз `launcher` у каталогу;
- GOG і Epic: пошук гульняў (рэестр GOG, маніфесты Epic) і ключы ў `stores`;
- подпіс каталога (ed25519), каб падмена файла на серверы нічога не давала.
